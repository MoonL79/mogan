# [0514] 跨版本首选项迁移

## 1 相关文档
- [0515.md](0515.md) — 首选项配置文件改为 JSON 格式（本任务依赖其引入的 JSON 读写与 lolly json 库能力）

## 2 任务相关的代码文件
- `src/System/Config/preferences.cpp` — 新增 `load_legacy_preferences` / `compare_versions` / `migrate_legacy_preferences`；
  `load_user_preferences` 在当前版本无 JSON 文件时走迁移
- `tests/System/Config/preferences_test.cpp` — 扩展迁移用例
- `CLAUDE.md` — 新增「首选项（preferences）与旧版本配置文件兼容性」规范

## 3 如何测试

### 3.1 确定性测试（单元测试）
```bash
xmake b preferences_test && xmake r preferences_test
```
用例：`system/<v1>/preferences.scm` + `system/<v2>/preferences.scm`（含冲突键）→ `load_user_preferences`
后键合并、高版本胜出、当前 `<cur>/preferences.json` 生成且内容正确；无旧配置时**不生成**空文件。

### 3.2 非确定性测试（交互验证）
1. 构造旧版本目录 `$TEXMACS_HOME_PATH/system/2026.2.3/preferences.scm`（写若干键），删除当前版本目录；
2. 启动新版本 → 确认旧首选项被读入并落到 `system/<当前版本>/preferences.json`；
3. 再次启动 → 直接读 JSON，不再触发迁移。

## 4 What
- 新增跨版本迁移：当前版本没有 `preferences.json` 时，扫描 `system/` 下含首选项文件的旧版本目录，
  按版本升序逐个导入，最新覆盖最旧，再立即以 JSON 落盘。
- `CLAUDE.md` 增加「涉及首选项改动务必适配旧版本配置文件」规范。

## 5 Why
- 首选项按版本分目录存储（`system/<XMACS_VERSION>/preferences.json`），版本号 bump 后新版本读写新目录，
  旧首选项永远不会被读 → 用户升级后表现为「每次更新都重置」。迁移逻辑让旧版本首选项在首次启动
  新版本时自动合并进来。

## 6 How
- `compare_versions (string, string)`：把 `tm_velopack.cpp` 的 semver 比较器移植到 lolly 类型
  （`tokenize`/`as_long_int`/`search_forwards`），核心段逐数字比较，预发布段按标识符比较
  （数字标识符 < 字母标识符，`rc10` > `rc2`），无预发布 > 有预发布。
- `load_legacy_preferences (url)`：复用 0515 删除的 `.scm` 解析（`block_to_scheme_tree` + `scm_unquote`）。
- `migrate_legacy_preferences ()`：
  1. `read_directory (system/)` 枚举；
  2. 过滤目录且含 `preferences.scm`/`preferences.json` 的版本目录；
  3. `merge_sort_leq<string, version_leq>` 按版本升序；
  4. 每个目录先 `.scm` 后 `.json`（json 覆盖 scm），后写覆盖先写 → 高版本优先；
  5. 导入任何键则 `user_prefs_modified=true`、`make_dir (head (get_tm_preference_path ()))` 后立即
     `save_user_preferences ()`。
- `load_user_preferences ()`：`preferences.json` 存在 → `load_json_preferences`；否则 →
  `migrate_legacy_preferences ()`。

## 7 已知问题
- 迁移只做一次：当前版本一旦生成 `preferences.json`，后续启动直接读它，不再扫旧目录（旧文件保留原样）。
